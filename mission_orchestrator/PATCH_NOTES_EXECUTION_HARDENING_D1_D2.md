# VulnDesk Execution Hardening D1/D2

Control version: `hybrid-event-driven-2.2-execution-hardening`

This patch is incremental over the closed Stage 2.1–2.5 baseline. It does not
change PolicyDecision ownership or PolicyDecision↔TaskContract binding.

## D1 — Source-sync semantics and source health

1. Adds typed event `SOURCE_SYNC_DEGRADED`.
2. Keeps three distinct execution outcomes:
   - `SUCCESS` → `SOURCE_SYNC_COMPLETED`
   - `DEGRADED` / bounded `PARTIAL` → `SOURCE_SYNC_DEGRADED`
   - actual failures/rate/transient conditions → `SOURCE_SYNC_FAILED`
3. A bounded `PARTIAL` no longer increments `failure_count` and no longer opens
   the source circuit breaker.
4. `RATE_LIMITED` uses backoff without being counted as source unavailability.
5. Only `FAILED`/`TRANSIENT` outcomes increment consecutive source failures.
6. Acquisition TaskContracts may end in `DEGRADED`, and `DEGRADED` is treated
   as a terminal task outcome for `finished_at`.
7. Source-state timestamps generated by Python are persisted consistently as
   UTC-naive MariaDB `DATETIME` values.
8. Adds optional corrective data script:
   `sql_update_cti_harmonized/04_execution_hardening_state_repair.sql`.

## D2 — Attack-path persistence hardening

`AttackPathReasoningAgent._persist_graph()` and `_persist_path()` no longer pass
`**graph` / `**path` into PyMySQL named parameters. They now construct explicit
scalar/JSON parameter maps. This removes the runtime error:

`TypeError: dict can not be used as parameter`

while preserving the authority invariant:

- `execution_authorized = 0`
- `authority_state = PROPOSED_INTELLIGENCE_PATH_ONLY`
