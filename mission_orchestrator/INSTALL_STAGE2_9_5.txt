VulnDesk Stage 2.9.5 — Integrity / Violation Probe Installation
===============================================================

Baseline:
  Vulndesk(20260829-081222).zip
  Vulndesk(20260829-081215).sql
  aptsGSS(20260829-081215).zip
  AptsGSS(20260829-081214).sql

Database migration:
  NONE REQUIRED.

aptsGSS source change:
  NONE REQUIRED for Stage 2.9.5.
  Keep the Stage 2.9.4 authoritative correlation endpoint active:
    GET /api/governance/correlation/missions/{mission_id}

Recommended install order:

1. Stop VulnDesk.
2. Back up the VulnDesk source directory and database.
3. Ensure aptsGSS Stage 2.9.4 is already running and healthy:
     Invoke-RestMethod "http://127.0.0.1:8770/health" | ConvertTo-Json -Depth 20
   Expected:
     governance_correlation_probe_mode = MISSION_SCOPED_AUTHORITATIVE_READ_ONLY
4. Apply the Stage 2.9.5 VulnDesk patch or replace with the supplied full Stage 2.9.5 source.
5. Start VulnDesk normally.
6. Verify health:
     Invoke-RestMethod "http://127.0.0.1:8765/health" | ConvertTo-Json -Depth 20
   Expected:
     control_version = hybrid-event-driven-2.16-integrity-violation-probe
     integrity_probe_mode = READ_ONLY_CANONICAL_LINEAGE_PLUS_AUTHORITATIVE_CORRELATION
7. Run focused tests:
     python -m pytest -q tests/test_integrity_violation_probe_stage2_9_5.py
8. Run broad regression:
     python -m pytest -q --ignore=tests/test_nvd_bulk_upsert.py
   The ignored test requires PyMySQL in the local Python environment. On the real
   VulnDesk venv, install requirements.txt and run the full suite without --ignore.
9. Run a FRESH governed mission with authorization + pre-dispatch revalidation.
10. Execute:
      .\STAGE2_9_5_ACCEPTANCE.ps1 -MissionId "<fresh-mission-id>"
11. Set @mission_id in STAGE2_9_5_ACCEPTANCE.sql and execute it against MariaDB.

Expected positive acceptance:
  mission integrity status = PASS
  violation_count = 0
  verification_complete = true

Important semantics:
  - Correct blocking after revocation is not a violation.
  - Dispatch after revocation is a CRITICAL violation.
  - Governance unavailability without a proven local violation is UNVERIFIABLE,
    not a fabricated integrity failure.
  - Stage 2.9.5 is read-only and does not repair persisted state.
