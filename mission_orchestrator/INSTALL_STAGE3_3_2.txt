Operational sequence for Stage 3.3.2:
  A. Mission must already satisfy guarded Stage-3.2.4 START_PLANNING.
  B. Stage-3.3.1 canonical Plan must already be registered.
  C. Read the current Plan id/version/hash and Mission state version.
  D. POST /api/missions/{mission_id}/planner-input-snapshot using those exact tokens.
  E. Treat the resulting snapshot as immutable planner input only.

Do not interpret the snapshot as execution authorization. Stage 3.3.2 performs no
planner invocation, task decomposition, Governance authorization query, target dispatch,
or target actuation.

Canonical invariants:
  SNAPSHOT != AUTHORIZATION
  CONTEXT != PERMISSION
  PLAN != AUTHORIZATION
  TASK != DISPATCH
  READINESS != PERMISSION
  PLANNER != GOVERNANCE
