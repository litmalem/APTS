Stage 3.1.4 - Governance & Authorization Binding Contract
=========================================================

Scope of patch
--------------
Apply this patch to D:\mission_orchestrator only.
No source-code change is required in VulnDesk or aptsGSS.
aptsGSS is, however, an active runtime dependency for Stage-3.1.4 binding/evaluation.

1. Stop the running mission_orchestrator service.

2. Back up:

   D:\mission_orchestrator

   and the Mission Orchestrator database.

3. Copy the Stage-3.1.4 patch files over:

   D:\mission_orchestrator

4. SQLite local mode
--------------------
No manual migration is required. Repository startup creates the five Stage-3.1.4 tables.

5. MariaDB/MySQL mode
---------------------
Apply the new migration after migrations 001-003:

   cd D:\mission_orchestrator
   mysql -u root -p < .\migrations\004_stage3_1_4_governance_authorization_binding_contract.sql

6. Configure the authoritative Governance endpoint
---------------------------------------------------
Default values are already compatible with the current local aptsGSS deployment:

   MISSION_GOVERNANCE_BASE_URL=http://127.0.0.1:8770
   MISSION_GOVERNANCE_TIMEOUT_SECONDS=3.0

PowerShell example for the current process:

   $env:MISSION_GOVERNANCE_BASE_URL = "http://127.0.0.1:8770"
   $env:MISSION_GOVERNANCE_TIMEOUT_SECONDS = "3.0"

7. Start / verify aptsGSS first
-------------------------------
The existing Governance service must be reachable at port 8770.
Verify:

   Invoke-RestMethod http://127.0.0.1:8770/health

Also verify that its emergency stop is NOT active before running acceptance:

   Invoke-RestMethod http://127.0.0.1:8770/api/governance/emergency-stop

Do not automatically release an emergency stop merely to pass acceptance. If it is active,
resolve the Governance safety state through the normal administrative process first.

8. Start Mission Orchestrator
-----------------------------

   cd D:\mission_orchestrator
   python .\run\run_mission_orchestrator.py --host 127.0.0.1 --port 8780

9. Run regression
-----------------
In another PowerShell:

   cd D:\mission_orchestrator
   python -m pytest -q

Expected current result:

   48 passed

10. Run Stage-3.1.4 acceptance
------------------------------

   Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
   .\STAGE3_1_4_ACCEPTANCE.ps1

Optional explicit endpoints:

   .\STAGE3_1_4_ACCEPTANCE.ps1 `
       -MissionBaseUrl "http://127.0.0.1:8780" `
       -GovernanceBaseUrl "http://127.0.0.1:8770"

Expected final result:

   STAGE 3.1.4 ACCEPTANCE: PASS

Safety / authority notes
------------------------
- aptsGSS / GOV-PLANE remains authoritative for ALLOW, DENY, REVIEW, approval,
  hard-deny, revocation, and emergency stop.
- Stage 3.1.4 records authorization provenance but never dispatches an action.
- An ALLOW still has execution_authorized=false.
- Pre-dispatch Governance revalidation remains mandatory for a later execution stage.
- Existing Stage-3.1.1 through Stage-3.1.3 acceptance artifacts are retained unchanged.
