STAGE 3.5.8 — TIMEOUT, CANCELLATION, ABORT & FAILURE PROPAGATION
================================================================

1. Replace the Mission Orchestrator source tree with this package.

2. Preserve the existing environment and database configuration.
   Repository migration level becomes 34 and introduces:

     migrations/034_stage3_5_8_timeout_cancellation_abort_failure_propagation.sql
     mission_execution_termination_controls
     mission_execution_outcome_propagations

3. Stage 3.5.8 reuses the exact runtime endpoint persisted by Stage 3.5.5.
   It does NOT resolve the runtime endpoint again.

   The downstream runtime must support the execution-control client contract:

     POST /api/execution/attempts/{execution_attempt_id}/control

   or an equivalent path configured through:

     MISSION_EXECUTION_CONTROL_PATH_TEMPLATE

4. Restart Mission Orchestrator on port 8780.

5. Verify /health:

     Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
     .\STAGE3_5_8_ACCEPTANCE.ps1

Important boundary:
- TIMEOUT/CANCEL/ABORT are runtime control intents against an already authorized,
  already delivered, RUNNING execution attempt.
- The control request itself does not transition Mission state.
- Stage 3.5.7 remains authoritative for terminal runtime result/evidence capture.
- Stage 3.5.8 verifies that immutable result and propagates non-success outcomes.
- SUCCEEDED is verified but does not complete the Mission.
- FAILED and TIMED_OUT fail the Mission.
- CANCELLED aborts the Mission, subject to prior TIMEOUT/ABORT intent semantics.
- No new Governance decision, endpoint resolution, dispatch redelivery, or target
  action dispatch is performed by Stage 3.5.8.
